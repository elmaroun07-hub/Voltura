# Block H-D17 — rate limits that count visitors, and caps on what the open routes store

Opened 23 Oct 2026 from the cloud session, operator instruction: "find a way yourself" (he had only a phone).
Branch `heatshield/h-d17`, cut from `main` = `a15dd1d` (live on both services, `/api/version` read 23 Oct 2026).

## Why

A friend reviewing the public `voltura-proof` repo raised that the site could be taken down. Reading the code at `a15dd1d`:

- **D17** (11 Sept 2026 report, recorded and never scheduled — the report's three severities had no place for availability): `POST /api/calculate` has no limiter, while each request makes one geocoder call, one NASA call and one insert.
- `POST /api/conversations` has no limiter and stores any title length — not in D1–D55.
- `POST /api/conversations/:id/messages` stores and sends to the model any content length and type.
- **Measured live, worse than either:** three consecutive GETs of `/api/screening/14021/export.csv` from one client each answered `RateLimit: remaining=9`. Render serves the API behind Cloudflare (`server: cloudflare`, `cf-ray`), and with `trust proxy 1` `req.ip` is a proxy address that changes per request. **No limiter in production ever counted a visitor twice** — optimize, chat messages and export included.

## Fence

API code, its tests, one web schema line (`location` max), no DDL, no data, no dependency change. `trust proxy` stays `1` (it only changes `req.ip`, now read by the request log alone). Out of scope, named: GET routes (`/api/history`, `/api/conversations`, PDF) have no limiter; a distributed flood from many addresses is not stopped by any per-client limit; a global geocoder budget (Nominatim's 1 req/s) does not exist.
